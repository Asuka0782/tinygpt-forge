# Line-by-line: training and experiment state

The baseline is intentionally single-process. Its value is a small state machine whose data split,
objective, validation selection, test use, randomness, and continuation state can all be audited.

## `training.py`

| Source lines | Explanation |
|---|---|
| [L1–L32](../../src/tinygpt_forge/training.py#L1) | Imports cover hashing/manifests, numeric metrics, atomic replacement, environment/time records, PyTorch/scaler, checkpoint APIs, config/data/model/tokenizer/TOML. The module has no network or paid-service dependency. |
| [L33–L54](../../src/tinygpt_forge/training.py#L33) | Frozen `TrainingConfig` declares batch/block/step counts, gradient accumulation, AdamW hyperparameters, clipping, validation schedule, split fractions, seed, device, precision, and fused preference. Defaults are a baseline contract, not automatically optimal. |
| [L55–L80](../../src/tinygpt_forge/training.py#L55) | Positive integer fields reject bools/zero; learning rate and clip are positive, decay nonnegative, betas in `[0,1)`. This baseline requires nonempty validation/test, a remaining train fraction, a closed device set, and FP32/BF16/FP16 precision names. Validation precedes data/model allocation. |
| [L81–L88](../../src/tinygpt_forge/training.py#L81) | `resume_contract` serializes every field except `max_steps`. A resumed run may extend duration but cannot silently change batch order, learning rate, dtype, split, or evaluation schedule. A scheduler would need its own state/contract in a future version. |
| [L89–L102](../../src/tinygpt_forge/training.py#L89) | `[training]` must be a mapping, unknown keys fail, and construction reruns all validation. A typo therefore cannot fall back to a default and contaminate comparisons. |
| [L103–L112](../../src/tinygpt_forge/training.py#L103) | `auto` resolves CUDA only when available; an explicit unavailable CUDA request fails instead of falling back to CPU and producing incomparable timings. Returned `torch.device` is used consistently by model/batches/scaler. |
| [L113–L121](../../src/tinygpt_forge/training.py#L113) | FP32 returns a no-op context. BF16/FP16 use device autocast; CPU FP16 is rejected for this baseline. Autocast selects operation dtypes but does not convert stored model parameters. BF16 does not need loss scaling's FP16 exponent protection. |
| [L122–L125](../../src/tinygpt_forge/training.py#L122) | Perplexity is `exp(cross_entropy)`; loss at/above 100 maps to infinity to avoid floating overflow. It is valid for this tokenization/objective but not directly comparable across different tokenizers. |
| [L126–L137](../../src/tinygpt_forge/training.py#L126) | Evaluation runs under inference mode and receives an explicit batch count, dtype/backend, and fixed sampler state. It returns mean next-token cross-entropy, not a cherry-picked minimum. |
| [L138–L150](../../src/tinygpt_forge/training.py#L138) | The original train/eval mode is remembered, model switches to eval, and validation sampler resets to identical windows on every call. Each `[B,T]` batch runs under the same autocast/backend; loss is converted to FP32 Python float. Mode is restored and arithmetic mean returned. If an exception occurs the training call aborts rather than continuing. |
| [L151–L160](../../src/tinygpt_forge/training.py#L151) | Corpus SHA-256 is streamed in chunks, binding a resume/result to exact input bytes without embedding the corpus. |
| [L161–L169](../../src/tinygpt_forge/training.py#L161) | Run JSON writes to a sibling temp and atomically replaces the final path. This prevents a successful-looking half manifest after interruption. |
| [L170–L179](../../src/tinygpt_forge/training.py#L170) | The public orchestration function requires corpus/run/model/training contracts explicitly and optional resume directory. It returns the same evidence object written to disk. |
| [L180–L188](../../src/tinygpt_forge/training.py#L180) | UTC start time and paths are normalized. A fresh run refuses any nonempty destination, protecting previous evidence. Resume requires an existing run directory. Creation is local and does not initialize Git or alter source data. |
| [L189–L208](../../src/tinygpt_forge/training.py#L189) | Corpus bytes are hashed, raw text is split first, and tokenizer fits train only. Fresh run atomically saves it; resume reloads and compares against a freshly derived train fingerprint. Train encoding is strict; validation/test allow `<unk>` so distribution shift is measured. IDs are rank-one CPU `long`. |
| [L209–L219](../../src/tinygpt_forge/training.py#L209) | Every split must exceed block size so `[T]` inputs have `[T]` following labels. Error names the split/count/required block before batch sampling. |
| [L220–L224](../../src/tinygpt_forge/training.py#L220) | Device resolves, training block cannot exceed model context, and config vocabulary is replaced by the train-fitted tokenizer size. Other model semantics remain immutable. |
| [L225–L239](../../src/tinygpt_forge/training.py#L225) | Global CPU and CUDA seeds precede model initialization. Model moves to device. Fused AdamW is effective only on CUDA and is recorded; betas/decay come from config. GradScaler is enabled only for CUDA FP16; the same API remains a no-op for FP32/BF16/CPU. |
| [L240–L263](../../src/tinygpt_forge/training.py#L240) | Train/validation/test own separate CPU generators with deterministic offset seeds and one target device. Fixed initial validation/test states are captured. Train state evolves and is checkpointed; validation/test reset for comparable windows. This separation prevents evaluation from changing training batch order. |
| [L264–L272](../../src/tinygpt_forge/training.py#L264) | Checkpoint directory and in-memory history/best/start/timestamps are initialized. `best=∞` guarantees the step-zero finite validation becomes a checkpoint. `resumed_from_step` remains explicit in the final manifest. |
| [L273–L288](../../src/tinygpt_forge/training.py#L273) | Resume first restores the safe bundle, then binds it to current corpus hash, tokenizer fingerprint, and full resume contract. This rejects “same architecture but different experiment” states. |
| [L289–L311](../../src/tinygpt_forge/training.py#L289) | Trainer fields are extracted and strictly typed: bool is not accepted as int, history entries are objects, and start time is text. Values require nonnegative current step, `0≤best≤current`, and finite best loss. Malformed but JSON-valid metadata fails before the loop. |
| [L312–L321](../../src/tinygpt_forge/training.py#L312) | Validated state replaces fresh counters/history/start time, dedicated train-batcher RNG is installed, and new target steps must exceed the checkpoint. The goal is continuation, not silently rerunning completed steps. |
| [L322–L344](../../src/tinygpt_forge/training.py#L322) | Nested `run_evaluation` updates outer best state. It evaluates fixed validation windows, appends step/loss/perplexity and optional train loss, and saves weights only on strict improvement. Test data is absent from this selection path. |
| [L345–L363](../../src/tinygpt_forge/training.py#L345) | Every positive-step evaluation writes a complete resume bundle: model, optimizer, current train sampler RNG, scaler, step/best/history, source/tokenizer identities, training contract, and original start time. Step zero has no optimizer transition and is not used as a resume bundle. |
| [L364–L383](../../src/tinygpt_forge/training.py#L364) | Fresh runs evaluate step zero. Each optimizer step zeros gradients with `set_to_none`, then performs configured microbatches. Raw loss is accumulated for reporting, while `micro_loss=loss/accumulation` makes the summed gradient equal a larger-batch mean. Scaled backward handles FP16; autograd saves activations for each microbatch only until its backward completes. |
| [L384–L394](../../src/tinygpt_forge/training.py#L384) | FP16 gradients are unscaled before norm clipping. Clipping bounds global norm, scaler steps/skips as needed, and updates scale. Mean train loss is reported. Validation/checkpoint runs at interval and always at final step; `model.train()` restores dropout afterward. |
| [L395–L404](../../src/tinygpt_forge/training.py#L395) | Final (“last”) weights are saved separately from validation-selected “best.” Only after training/selection ends is the test sampler evaluated, so test never chooses hyperparameters/checkpoint. This manifest reports last-model test loss explicitly. |
| [L405–L424](../../src/tinygpt_forge/training.py#L405) | Result schema records status/times/resume source, corpus basename/hash, tokenizer identity/OOV counts, and exact split sizes. No absolute local path or corpus content is written. OOV counts expose validation/test characters absent from train vocabulary. |
| [L425–L444](../../src/tinygpt_forge/training.py#L425) | Resolved model/training configs, Python/PyTorch/platform/device/GPU/fused effectiveness, parameter count, best validation metrics, last-test metrics, and full history form the evidence card. Atomic `run.json` write happens last, then the identical object returns to CLI/tests. One short run is pipeline evidence, not a language-quality claim. |
