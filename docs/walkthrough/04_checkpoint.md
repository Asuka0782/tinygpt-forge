# Line-by-line: safe weights and complete training checkpoints

The design separates tensor bytes (safetensors) from bounded, inspectable structure (JSON). SHA-256
detects accidental or malicious modification but does not authenticate the publisher; users still
need a trusted source and resource limits.

## `checkpoint.py`

| Source lines | Explanation |
|---|---|
| [L1–L23](../../src/tinygpt_forge/checkpoint.py#L1) | Imports cover hashing, JSON writing, atomic replacement, mappings/paths, PyTorch, safetensors, scaler, config/model, and the shared bounded strict JSON reader. Two independent format strings version weights-only and full-training schemas. No pickle loader is imported. |
| [L24–L31](../../src/tinygpt_forge/checkpoint.py#L24) | `_sha256` streams a file in 1 MiB chunks, so hashing memory is (O(1)) in checkpoint size. The empty byte sentinel stops `iter`; the final hexadecimal digest is stored in JSON. Hashes prove byte equality, not who created the file. |
| [L32–L41](../../src/tinygpt_forge/checkpoint.py#L32) | `save_weights` normalizes/creates the directory and names final plus sibling temporary files. Keeping temp on the same filesystem allows `os.replace` to be atomic on supported local filesystems. |
| [L42–L60](../../src/tinygpt_forge/checkpoint.py#L42) | `save_model` handles tied parameters and writes safetensors metadata to temp; replace publishes tensor bytes first. The manifest records full model config, unique parameter count, local filename, and hash. JSON is written/replaced last, so readers never see a new manifest pointing to unfinished bytes. A crash can leave a `.tmp`, but `.gitignore`/hygiene prevents publication. |
| [L61–L69](../../src/tinygpt_forge/checkpoint.py#L61) | `load_weights` is keyword-only for device/hash policy and returns a newly constructed model. Hash verification defaults on; disabling it is an explicit local diagnostic choice, not the training-resume path. |
| [L70–L86](../../src/tinygpt_forge/checkpoint.py#L70) | The shared reader bounds metadata and requires strict unique-key finite JSON before the exact format check. Config must be an object. `Path(name).name == name` rejects directories and `../` traversal, constraining tensors to the checkpoint directory. The expected hash must match bytes. |
| [L87–L95](../../src/tinygpt_forge/checkpoint.py#L87) | Config reconstruction reruns all model invariants, then allocates/moves the model. Safetensors `load_model(..., strict=True)` accounts for tied weights; any missing/unexpected key fails. Large untrusted tensor shapes can still exhaust memory, so safetensors is not a sandbox. |
| [L96–L111](../../src/tinygpt_forge/checkpoint.py#L96) | `_encode_json_value` recursively permits only JSON primitives, lists, tuples with an explicit `__tuple__` tag, and string-keyed dicts. Rejecting non-string keys prevents collisions such as `1` and `"1"`. Unsupported objects fail instead of falling back to pickle/repr. |
| [L112–L124](../../src/tinygpt_forge/checkpoint.py#L112) | Decode recursively reverses lists and exact single-key tuple tags. Ordinary objects stay dictionaries. It does not import or instantiate arbitrary classes, so metadata cannot trigger code execution. |
| [L125–L140](../../src/tinygpt_forge/checkpoint.py#L125) | Optimizer `state_dict` mixes tensors with scalar/list/group structure. The loop separates them by parameter ID and state name. `/` is forbidden because tensor keys use it as a namespace. Tensors are detached/contiguous; scalars use the restricted codec. |
| [L141–L163](../../src/tinygpt_forge/checkpoint.py#L141) | Tensor state is written atomically to `optimizer.safetensors`. `optimizer.json` records its local name/hash, scalar states, and encoded param groups, then is atomically replaced. Splitting preserves exact optimizer semantics without `torch.save`. |
| [L164–L184](../../src/tinygpt_forge/checkpoint.py#L164) | `_read_optimizer_state` strictly and boundedly reads JSON before mutating the optimizer. It validates schema/local path/file hash and compares the hash copied into `training.json`; this cross-manifest check catches mixed files. Tensors load only after validation. |
| [L185–L204](../../src/tinygpt_forge/checkpoint.py#L185) | Tensor names must parse as `state/<integer id>/<name>`. Scalar state is type-checked/decoded and merged per ID; param groups must decode to a list. Installation is postponed until all bundle components pass preflight. |
| [L205–L229](../../src/tinygpt_forge/checkpoint.py#L205) | `_save_rng_states` captures global CPU RNG, dedicated batcher RNG, and every available CUDA device RNG as byte tensors. They are saved atomically in safetensors with local file/hash and CUDA count. Python/NumPy RNG are absent because this loop does not use them. |
| [L230–L254](../../src/tinygpt_forge/checkpoint.py#L230) | `_read_rng_states` validates local path/hash and required CPU keys without changing global RNG. CUDA count must be a real nonnegative integer equal to the current machine count, or exact continuation is rejected. |
| [L255–L266](../../src/tinygpt_forge/checkpoint.py#L255) | `save_training_checkpoint` requires all continuation state explicitly as keywords: model, optimizer, batcher RNG, scaler, trainer metadata, destination. This makes omissions visible at the call site. |
| [L267–L280](../../src/tinygpt_forge/checkpoint.py#L267) | Model, optimizer, and RNG sub-artifacts are saved first. `training.json` repeats model/optimizer hashes, nests RNG manifest, and encodes scaler/trainer state. Duplicate hashes bind independent files into one logical bundle. |
| [L281–L288](../../src/tinygpt_forge/checkpoint.py#L281) | Bundle manifest is the final atomic publish step. The directory as a whole is not rollback-transactional: an interruption can invalidate previous names, but hash checks make the partial mix fail closed. |
| [L289–L300](../../src/tinygpt_forge/checkpoint.py#L289) | `load_training_checkpoint` accepts already constructed model/optimizer/scaler, directory, and target device. It returns validated trainer metadata plus batcher RNG state. |
| [L301–L319](../../src/tinygpt_forge/checkpoint.py#L301) | Training/model manifests pass the shared size/strict-JSON checks and format validation. Config must match the supplied model. Weight filename is local; bytes and both manifests must agree. No model parameter has changed yet. |
| [L320–L337](../../src/tinygpt_forge/checkpoint.py#L320) | Optimizer state is read and cross-bound into memory. Scaler structure, RNG tensors/device count, and trainer-state object are decoded/validated. Failure here leaves model, optimizer, scaler, and global RNG untouched. |
| [L338–L346](../../src/tinygpt_forge/checkpoint.py#L338) | Only after preflight does strict model loading mutate parameters, followed by optimizer, scaler, CPU RNG, and CUDA RNG states. Installation cannot be universally atomic against framework/OOM errors, so callers abort on any exception. |
