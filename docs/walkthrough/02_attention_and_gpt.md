# Line-by-line: attention and the complete decoder

This section follows tensors through the two attention backends and then through the model stack.
Notation matches the first walkthrough: input hidden states are `[B,T,C]`, split heads are
`[B,Hq/Hkv,T,Dh]`, attention scores are `[B,Hq,Q,K]`, and logits are `[B,T,V]`.

## `model/attention.py`

| Source lines | Explanation |
|---|---|
| [L1–L18](../../src/tinygpt_forge/model/attention.py#L1) | The module promises shared parameters between readable and SDPA paths. Imports cover scale math, structured outputs, PyTorch, Static Cache, validated config, and RoPE. `KeyValue` is a type alias for raw `(key,value)` tensors; it creates no runtime wrapper and keeps cache signatures readable. |
| [L19–L27](../../src/tinygpt_forge/model/attention.py#L19) | `AttentionOutput` groups three semantically different products: residual-ready hidden states `[B,T,C]`, optional manual probabilities `[B,Hq,Q,K]`, and optional raw Dynamic K/V `[B,Hkv,S,Dh]`. Optional fields prevent SDPA from pretending it exposes probabilities it never materializes. |
| [L28–L37](../../src/tinygpt_forge/model/attention.py#L28) | `repeat_key_value` validates rank/group count, returns the same tensor for MHA (`groups=1`), or repeats Hkv heads to Hq for GQA/MQA attention math. Expansion happens after cache storage, so cache memory remains proportional to Hkv. `repeat_interleave` may allocate; a native GQA kernel could avoid it, which is why the benchmark records the dispatched backend instead of claiming optimal GQA. |
| [L38–L52](../../src/tinygpt_forge/model/attention.py#L38) | The module owns Q/K/V/output projections, residual dropout, and RoPE. Q width is `Hq*Dh=C`; K/V width is `Hkv*Dh`, smaller under GQA. All linears are bias-free. Putting one projection set above both backends is the core equivalence design: only the attention computation changes. |
| [L53–L59](../../src/tinygpt_forge/model/attention.py#L53) | `_project` reads `[B,T,C]`. Q projection returns `[B,T,Hq*Dh]`, `view` splits heads, and `transpose(1,2)` produces `[B,Hq,T,Dh]`. This is a view/stride change until later operations require layout. |
| [L60–L72](../../src/tinygpt_forge/model/attention.py#L60) | K/V follow the same transformation with Hkv. RoPE rotates Q and K at identical absolute positions; V is intentionally unchanged because position enters attention similarity, not the values. Return shapes are Q `[B,Hq,T,Dh]` and raw K/V `[B,Hkv,T,Dh]`. |
| [L73–L81](../../src/tinygpt_forge/model/attention.py#L73) | `_manual_attention` receives already head-expanded K/V plus `past_length`. Keyword-only past length makes cached mask alignment explicit. It returns both attended values and the probabilities needed for teaching/inspection. |
| [L82–L90](../../src/tinygpt_forge/model/attention.py#L82) | `Q @ Kᵀ` produces `[B,Hq,Q,K]`; scaling by (1/\sqrt{D_h}) prevents score variance from growing with head width. Absolute query positions are `past…past+Q-1`; keys are `0…K-1`. Broadcasting their comparison creates a Boolean `[Q,K]` causal mask that is correct even when `Q≠K` during cached decode. |
| [L91–L98](../../src/tinygpt_forge/model/attention.py#L91) | Future scores become `-inf`, so softmax probability is zero. Dropout is applied to probabilities only during training, then `[B,Hq,Q,K] @ [B,Hq,K,Dh]` yields `[B,Hq,Q,Dh]`. Returning post-dropout probabilities matches the actual values used in the weighted sum. Materializing scores/probabilities costs (O(BH_qQK)) memory and is why this path is educational rather than the fast default. |
| [L99–L112](../../src/tinygpt_forge/model/attention.py#L99) | The public `forward` exposes explicit backend, observability, Dynamic cache, Static cache, and layer index controls. Static and Dynamic caches are separate types because one returns tensors while the other mutates preallocated storage. |
| [L113–L123](../../src/tinygpt_forge/model/attention.py#L113) | Input must be `[B,T,C]`. Backend defaults to config and must be in the closed validated set. Attention probabilities are rejected for SDPA instead of silently returning `None`; callers requesting an observable matrix must use the manual path. |
| [L124–L129](../../src/tinygpt_forge/model/attention.py#L124) | Dynamic and Static cache inputs are mutually exclusive. Static storage needs a layer index so all blocks address distinct tensors. These checks occur before projection/GPU work. |
| [L130–L145](../../src/tinygpt_forge/model/attention.py#L130) | Past length comes from Static logical state or Dynamic tensor length. Dynamic K/V must both be rank four with identical `[B,Hkv,S,Dh]` shape. This stage checks geometry; device/dtype are checked after current projection gives the authoritative expected values. |
| [L146–L152](../../src/tinygpt_forge/model/attention.py#L146) | If the caller omits positions, absolute IDs start at `past_length`. This single offset is what makes incremental RoPE logits match full-sequence logits. The vector is `[T]` on the activation device. |
| [L153–L161](../../src/tinygpt_forge/model/attention.py#L153) | Current Q/K/V are projected once. Static mode writes raw K/V to this layer's fixed buffer at `past_length` and receives prefix views `[B,Hkv,past+T,Dh]`. The assertion narrows the type after the earlier runtime check. |
| [L162–L173](../../src/tinygpt_forge/model/attention.py#L162) | Dynamic mode first rejects mixed device/dtype, then concatenates old and new K/V along sequence. This is semantically simple but reallocates/copies growing tensors. When `use_cache` is true, Dynamic mode returns the raw prefix; Static mode returns no duplicate tuple because storage is already owned externally. |
| [L174–L177](../../src/tinygpt_forge/model/attention.py#L174) | Raw Hkv states are expanded to Hq only immediately before attention. Q already has Hq heads. Both resulting K/V shapes are `[B,Hq,K,Dh]`. |
| [L178–L185](../../src/tinygpt_forge/model/attention.py#L178) | Manual selection calls the explicit score/mask/softmax implementation and retains probabilities. The same projected Q/K/V and `past_length` feed this path, forming a numerical oracle for SDPA. |
| [L186–L199](../../src/tinygpt_forge/model/attention.py#L186) | SDPA receives dropout `0` in eval and configured dropout in training. For a square no-past sequence, `is_causal=True` lets PyTorch choose an optimized causal kernel. Cached non-square attention instead builds the same absolute `[Q,K]` Boolean mask as the manual path; using only `is_causal=True` here can align the triangle to the wrong corner. |
| [L200–L207](../../src/tinygpt_forge/model/attention.py#L200) | `scaled_dot_product_attention` consumes Q/K/V plus either explicit mask or causal flag and returns `[B,Hq,Q,Dh]`. PyTorch decides the actual kernel from device, dtype, shape, build, and backend policy; the code therefore says SDPA, not “FlashAttention.” |
| [L208–L215](../../src/tinygpt_forge/model/attention.py#L208) | Head output transposes to `[B,Q,Hq,Dh]`; `contiguous` is required before viewing the two final dimensions as `C`. Output projection and residual dropout produce `[B,Q,C]`. The structured return carries observability/cache products without storing request state on the module. |

## `model/gpt.py`

| Source lines | Explanation |
|---|---|
| [L1–L16](../../src/tinygpt_forge/model/gpt.py#L1) | Imports assemble the decoder from validated config, loss, attention/cache types, and component modules. There is no tokenizer, filesystem, or provider dependency inside the model definition. |
| [L17–L25](../../src/tinygpt_forge/model/gpt.py#L17) | `CausalLMOutput` makes logits `[B,T,V]` mandatory and loss/attention/cache conditional. A dataclass gives named fields without forcing a heavyweight framework output type. |
| [L26–L37](../../src/tinygpt_forge/model/gpt.py#L26) | `DecoderBlock` is pre-normalized: RMSNorm precedes attention and FFN. Two residual sublayers keep width `C`; dropout after the FFN is separate from attention's output/probability dropout. Modules are registered so optimizers, checkpoints, device moves, and train/eval recursion work automatically. |
| [L38–L50](../../src/tinygpt_forge/model/gpt.py#L38) | The block's keyword-only controls mirror attention. It returns hidden states plus optional observation/cache data rather than mutating global fields, which keeps concurrent ordinary forward calls independent. |
| [L51–L62](../../src/tinygpt_forge/model/gpt.py#L51) | First, `norm(x)` feeds attention and all backend/cache arguments flow through. Residual addition computes `x + Attn(Norm(x))`; the second computes `x + Dropout(SwiGLU(Norm(x)))`. Shapes stay `[B,T,C]`. Pre-norm gives gradients an identity residual path, though it is a design choice rather than a guarantee against all instability. |
| [L63–L79](../../src/tinygpt_forge/model/gpt.py#L63) | `TinyGPT` registers token embedding `[V,C]`, embedding dropout, `L` blocks, final norm, and LM head `[C,V]`. `self.apply` initializes every Linear/Embedding before optional weight tying. Assigning the exact Parameter object—not copying values—makes embedding and LM head share storage and gradients, reducing parameters by `V*C`. |
| [L80–L84](../../src/tinygpt_forge/model/gpt.py#L80) | The static initializer visits submodules through `apply` and samples Linear/Embedding weights from `N(0,0.02²)`. It leaves RMSNorm scales at one. This simple baseline is reproducible after seeding but is not claimed as a scale-optimal initialization recipe. |
| [L85–L100](../../src/tinygpt_forge/model/gpt.py#L85) | `forward` accepts integer IDs plus optional already-shifted targets, backend observations, or one cache representation. The docstring explicitly distinguishes aligned targets from the separate unshifted loss helper, preventing off-by-one training objectives. |
| [L101–L108](../../src/tinygpt_forge/model/gpt.py#L101) | Input IDs must be non-empty rank-two integer tensors `[B,T]`. Embedding later performs vocabulary-range checking. Rejecting floats early avoids accidental truncation/casting of IDs. |
| [L109–L118](../../src/tinygpt_forge/model/gpt.py#L109) | Dynamic and Static cache APIs cannot be mixed. Static cache requires `use_cache=True`, identical immutable model config, and matching batch size. Device/dtype and capacity are enforced by cache writes. |
| [L119–L137](../../src/tinygpt_forge/model/gpt.py#L119) | No Dynamic input becomes an `L`-tuple of `None`, so the layer loop is uniform. Supplied tuples must have one entry per block. The set of K sequence lengths must contain at most one value, and partial cached/uncached layers are rejected once length is nonzero. These invariants stop different blocks from attending over different histories. |
| [L138–L145](../../src/tinygpt_forge/model/gpt.py#L138) | Total context is past plus current `T`; exceeding `max_seq_len` fails before embedding or cache writes. This bounds RoPE positions and memory but does not implement sliding-window truncation. |
| [L146–L160](../../src/tinygpt_forge/model/gpt.py#L146) | Embedding maps `[B,T]→[B,T,C]`. Observation/cache lists are allocated only when requested. `zip(..., strict=True)` is a second structural guard. Each block receives its own past tuple or Static layer index, and the hidden stream remains `[B,T,C]`. |
| [L161–L168](../../src/tinygpt_forge/model/gpt.py#L161) | Requested probabilities and Dynamic caches must actually be returned; otherwise a runtime contract error stops the call. Appending preserves layer order. Static mode skips a returned list because tensors already reside in external storage. |
| [L169–L172](../../src/tinygpt_forge/model/gpt.py#L169) | Static logical length advances only after every block completes. This is a small commit protocol: a failed block may have written bytes, but those bytes never become part of the visible prefix. |
| [L173–L184](../../src/tinygpt_forge/model/gpt.py#L173) | Final RMSNorm and tied/untied LM head produce `[B,T,V]`. Loss is computed only when targets exist. Mutable lists become immutable tuples in the API return, and all four semantic products are named. |
| [L185–L192](../../src/tinygpt_forge/model/gpt.py#L185) | `self.parameters()` already deduplicates a tied Parameter object, so summing `numel` counts shared embedding/head storage once. The optional generator filter counts only trainable parameters, useful for future LoRA evidence without changing the base model. |
